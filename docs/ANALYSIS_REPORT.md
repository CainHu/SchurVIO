# 视觉后验作用、协方差与噪声敏感度分析

配套交互式报告：`out/report.html`（自包含 HTML，浏览器直接打开）。

## 生成方法

```bash
cmake --build cmake-build-release --target VinsAnalysis VinsReport
./cmake-build-release/VinsAnalysis.exe 400 base 1.0
./cmake-build-release/VinsReport.exe
```

报告包含总体精度、可旋转 3D 轨迹、GT/EST/特征点/机体坐标系、视觉更新
先验与后验、误差与协方差、零偏与重力、噪声扫描及观测量统计。

## 一、协方差负值的真正原因与修复

旧版本在 100 秒仿真中有 `142/2001` 帧的速度协方差块 trace 为负，首次出现于
约 92.9 秒。最初将其归因于视觉更新中的 Joseph 等价形式，这是不准确的。

分阶段诊断得到：

- 负 trace 在视觉更新之前已经存在；视觉更新首次引入负 trace 的次数为 0。
- 联合协方差的最小特征值从约 0.8 秒起逐渐变负，而视觉更新前后几乎不变。
- 根因在 IMU 预测：旧代码只传播左上角 18×18 的 INS 协方差，却没有传播
  INS 与滑窗增广位姿之间的互协方差。

联合状态写成

```text
P = [ P_ii  P_ic ]
    [ P_ci  P_cc ]
```

预测时增广位姿保持不变，完整状态转移为 `F = diag(A, I)`，因此必须执行：

```text
P_ii' = A P_ii A^T + Q
P_ic' = A P_ic
P_ci' = P_ic'^T
P_cc' = P_cc
```

旧实现只更新 `P_ii`，却冻结 `P_ic`。这些块不再描述同一个随机变量经过同一状态
转移后的联合分布，因此整个 198×198 协方差会变成不定矩阵。

修复后使用显式合同变换并同步传播互协方差。结果：

| 指标 | 修复前 | 修复后 |
|---|---:|---:|
| trace 为负的帧数 | 142 / 2001 | **0 / 2001** |
| 联合协方差最小特征值 | 约 -40 | **约 -2e-12** |
| 位置 RMSE | 0.1058 m | **0.0701 m** |
| 速度 RMSE | 0.0216 m/s | **0.0133 m/s** |
| 位置改善率 | 50.5% | **81.1%** |

`-2e-12` 相对协方差矩阵尺度是正常的浮点舍入误差，不是数值不定。两轮稳定
计时中，完整互协方差传播与旧实现的总运行时间均约 11.2 秒，没有可测量开销。

## 二、Joseph 形式是否需要替换

当前视觉标量序贯更新已经是 Joseph 形式的代数等价展开：

```text
P+ = (I-KH) P (I-KH)^T + K R K^T
```

Joseph 形式的目的正是比简化式 `P+ = (I-KH)P` 更好地保持对称性和半正定性。
本次诊断证明视觉更新不是负协方差的来源，因此改成简化式不会解决问题，反而会
降低数值稳定性；直接改成平方根滤波也属于高成本绕过根因。

修复联合预测后，当前 Joseph 等价实现可以保留。若将来仍出现超出 `1e-10` 相对
量级的负特征值，再考虑平方根协方差或 UD 滤波。

## 三、视觉后验修正作用

修复后基线（`uv_var=400`, `proc_scale=1`）：

| 指标 | 数值 |
|---|---:|
| 位置 RMSE | 0.0701 m |
| 速度 RMSE | 0.0133 m/s |
| 姿态 RMSE | 0.000731 rad（0.0419°） |
| 最大位置误差 | 0.1299 m |
| 视觉更新让位置更接近 GT 的比例 | **81.1%** |

平均视觉位置修正量仍小于全局位置误差。这部分主要来自 VIO/SLAM 的 gauge 自由度：
视觉不能压缩全局平移、全局旋转和尺度方向，故全局坐标下的位置协方差仍会增长。
这不等同于协方差失去正定性；前者是可观测性问题，后者是数值/实现错误。

## 四、修复后的噪声敏感度

旧实现中 `uv_var=200`、`proc_scale=2` 会断崖发散。补全互协方差传播后，这些
发散均消失，说明旧“稳定边界”主要是错误协方差结构造成的，而非传感器噪声本身。

### 量测噪声

| uv_var | 位置 RMSE |
|---:|---:|
| 4 | 0.0309 m |
| 10 | 0.0326 m |
| 25 | 0.0429 m |
| 100 | 0.0586 m |
| 200 | 0.0640 m |
| 400（默认） | 0.0701 m |
| 1600 | 0.0846 m |
| 6400 | 0.1259 m |

扫描范围全部稳定。当前仿真中减小 `uv_var` 会提高视觉权重并改善精度，但不能直接
据此把真实系统参数设成 4；应根据像素噪声、归一化坐标尺度及残差统计重新标定。

### 过程噪声缩放

| scale | 位置 RMSE |
|---:|---:|
| 0.5 | 0.0762 m |
| 1.0（默认） | 0.0701 m |
| 2.0 | 0.0644 m |
| 5.0 | 0.0578 m |
| 10.0 | 0.0514 m |
| 20.0 | 0.0423 m |
| 100.0 | 0.0286 m |

扫描范围也全部稳定。更大的过程噪声使滤波器更愿意接受视觉修正，在当前使用真值
landmark 的理想仿真里持续改善结果。真实系统不能照搬该极值，应通过 IMU Allan
方差、残差白化和 NEES/NIS 一致性来标定。

## 五、结论

1. 协方差负值不是 Joseph 形式造成的。
2. 根因是预测阶段漏掉 `P_INS,clone` 的传播。
3. 显式执行完整联合合同变换后，负 trace 清零，协方差只剩机器精度量级的微小负值。
4. 修复同时显著提升了轨迹精度和视觉后验的修正方向正确率。
5. 旧噪声扫描结论已经失效，报告和本文均已使用修复后的数据重新生成。
